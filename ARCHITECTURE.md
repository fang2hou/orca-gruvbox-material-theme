# Architecture

The plugin is content only: Orca reads `orca-plugin.json`, the app themes in `themes/` and the terminal themes in `terminal/`. All of that content is generated by a small Python package from sainnhe's upstream palette, so the decisions live in code and every variant follows the same rules.

## Codebase map

- **palette**: upstream background and foreground palettes, copied verbatim. Three backgrounds (`hard`, `medium`, `soft`) times three foregrounds (`material`, `mix`, `original`) times two modes.
- **themes**: maps palette roles onto Orca tokens, TextMate scopes and terminal colors, and applies the contrast nudges.
- **orca_check**: a port of the contrast check Orca's renderer runs before painting a plugin theme.
- **build**: the `gruvbox-orca` CLI; writes the content, reports adjustments, and fails when generated files are stale or Orca would drop a color.
- **cover**: renders the plugin cover from the generated JSON.

## Invariants

1. Generated content is never edited by hand. `themes/`, `terminal/` and the manifest's `contributes` come from `mise run generate`, and `mise run check` fails when they drift.
2. Every generated theme passes Orca's contrast check with nothing dropped, and no syntax color falls under Monaco's 3:1 floor. The build refuses to write otherwise.
3. Palette values stay identical to upstream. A color only moves when a rule fails, by the smallest 1% step toward `fg0`, and `mise run report` lists every move.
4. `orca_check` behaves like Orca's renderer. It was verified against Orca's own implementation, loaded from the app bundle, on generated and randomly perturbed themes with no disagreement; re-verify after Orca changes its check.
5. Plugin, theme ids and titles are stable, because installed users select themes by them.

## Orca's contrast check

Before painting a plugin theme, Orca's renderer checks a fixed list of surface/text pairs and silently drops both tokens of any failing pair, painting its own fallback instead. The floors are 4.5:1 for text (including chat, diff lines and links), 3:1 for git decorations on `--sidebar`, and 2:1 for focus rings and the active-tab line. Monaco separately drops any syntax color under 3:1 on the editor, and skips the whole editor theme when the foreground misses 4.5:1.

| Rule | Floor | Where it applies |
| --- | --- | --- |
| Muted text on every surface it sits on: `bg0`, tab strip, popover, muted fill, both hover fills, Orca's default tinted sidebar and its hover | 4.5:1 | Every variant; the binding surface is the hover fill (Dark `bg3`, Light `bg5`) |
| Primary button text on `green`: `bg0`, else white (Light) or `bg_dim` (Dark) | 4.5:1 | Every Light variant uses white |
| Light `--accent` against Orca's default tinted sidebar | 1.15:1 | Hard Light, where `bg5` stays too close to the tint |
| Links on `bg0` and popovers | 4.5:1 | Light Medium/Soft Material, Dark Soft Original |
| Chat diff text (Orca's `fg0` 30% into `--diff-*`) on `bg_diff_*` | 4.5:1 | Light Soft Material/Mix, Light Medium Material; git colors keep the palette value |
| Chat inline code (`aqua`) on Orca's inline-code fill | 4.5:1 | Every variant except Dark Hard, slightly |
| Git decorations on the sidebar | 3:1 | `grey1` ignored files on Soft Light |
| Syntax colors on `bg0` | 3:1 | `grey1` comments on Soft Light |

Orca's **Tinted** left-sidebar mode recomputes the sidebar tokens itself (`color-mix(#18181b 8%, --background)`, hover `fg 9%` over that) but still paints ghost buttons, such as Settings' **Back to app**, with `--accent`. Light `bg3` nearly matches the tinted sidebar (1.01:1 on Medium), so Light uses `bg5`, darkened further on Hard Light where `bg5` reaches only 1.06:1.

## Palette mapping

| Orca role | Palette role |
| --- | --- |
| App, editor, sidebars, cards and the active tab | `bg0` |
| Tab strip and inactive tabs | `bg_dim`, recessed so the active tab opens into the editor |
| Menus, popovers and dialogs | `bg1` |
| Secondary and muted fills (badges, chips, tracks) | Dark `bg_current_word`, Light `bg4` |
| Sidebar hover and selected rows, terminal selection | `bg3` (upstream's `Visual`) |
| Ghost-button and menu hover, selected fills, editor current line | Dark `bg3`, Light `bg5` (see Tinted above) |
| Main text | `fg0` |
| Muted text, line numbers | `grey2`, nudged toward `fg0` |
| Inputs | Dark `bg1`, Light `bg3` |
| Borders and split dividers | Dark `bg3`, Light `bg5` |
| Primary action, focus ring, cursor, active tab line | `green` |
| Links | `blue` |
| Editor selection | `fg0` at 15% (Dark) or 12% (Light) opacity |
| Diff lines, changed characters, gutter | `bg_diff_*`, `bg_visual_*`, the hue mixed 30% into `bg0` |
| Git decorations | `green` added and untracked, `orange` modified, `red` deleted, `blue` renamed, `aqua` copied, `grey1` ignored |
| Chat bold text, inline code | `fg0`, `aqua`; chat fills stay Orca's own `fg0` mixes |
| Charts | `green`, `orange`, `blue`, `purple`, `yellow` |

Red stays reserved for deletions and errors, so the accent is green. Muted fills are deliberately not `bg0`: Orca paints badges, keyboard hints and progress tracks with them, and a `bg0` fill made those shapes disappear. Orca does not expose separate tokens for the editor's current line, line numbers and cursor; it paints them with `--accent`, `--muted-foreground` and `--ring`.

## Syntax mapping

The syntax rules follow gruvbox-material's own highlight groups as tuned in the author's Neovim setup: red keywords; orange storage modifiers, operators, tags and labels; `fg0` variables and parameters; blue properties, keys and links; aqua strings and constants; green escapes, regular expressions, tag delimiters and attributes; bold green functions; bold yellow types with plain yellow namespaces; purple numbers, booleans, built-ins, decorators and preprocessor; italic `grey1` comments; `grey1` separators.

Orca's editor maps every plain identifier to the `variable` scope, so variables stay `fg0` instead of coloring every name. A deeper scope that sets an empty `fontStyle` clears bold inherited from a broader one (property names under `support.type`, namespaces under `entity.name.type`). Markdown uses orange bold headings, red list markers, blue underlined links, aqua inline code and italic `grey1` quotes.

## Terminal mapping

Terminal colors follow upstream's terminal mapping: black is Dark `bg5` or Light `fg0`, white is Dark `fg0` or Light `bg5`, cyan is `aqua`, and bright colors equal the normal ones. Bright black is `grey1` in every variant, because shells draw dimmed text (autosuggestions, hints) with it and upstream's value made that text identical to the foreground in Light. `cursorAccent` is `bg0`, so a block cursor keeps the glyph under it readable.
